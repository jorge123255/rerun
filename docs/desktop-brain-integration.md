# Desktop Brain integration repair

The imported D/G/H handoffs were not yet a combined implementation. The desktop Brain now has one engine-owned repository, `createDesktopBrainPagesStore`, used by page routes, proposal routes and coworker tools. UI server routes proxy the authenticated local engine; they do not import or open its filesystem/database.

## Root wiring

- During explicit startup/bootstrap call `initializeDesktopBrainStore()` from `apps/engine/src/desktop/brain-pages-router.ts`. It prepares and pins the database path, runs the original Brain DB migrations, creates/verifies the Markdown directory, initializes receipt/publication tables, recovers committed publications and rebuilds the local index. Invoke at every boot after the desktop data root exists. Request handlers never initialize schemas.
- Mount `createDesktopBrainPagesRouter()` at `/desktop/brain/pages` and `createDesktopBrainProposalsRouter()` from `brain-proposals-router.ts` at `/desktop/brain/proposals`, behind existing engine authentication and exact desktop allowlist. Human routes support only original page CRUD/history/revert/confirm and proposal GET/count/POST accept/dismiss. No hosted seed/write/embedding route.
- Register only `desktopBrainTools(ctx)` for the explicit `brain` coworker grant. It exports `brain_read`, `brain_search`, `brain_propose`; no `brain_write`. Every tool rereads enabled/deleted/grant state; proposals recheck immediately before transaction commit. Chat output keeps `{status,proposalId,slug,title,message}` for the proposal card.
- Build the shared client with `createDesktopBrainPagesActions(countDesktopBrainProposals)`. Interface: `load`, `readPage`, `savePage(slug,input,requestId)`, `deletePage(slug,expectedHash,requestId)`, `readRevision`, `revertPage(slug,revisionId,expectedHash,requestId)`, `confirmSections(slug,headings,expectedHash,requestId)`; optional final AbortSignal. `load` returns `{pages,openProposals}`. Only confirmed 404 reads return null; other failures throw.
- Mount `DesktopBrainProposalsPanel` with `onOpenPage` and `onDecided({slug,requestId})`. Forward decisions to the pages panel refresh input. Clean page/history refreshes; dirty local drafts remain intact with a conflict notice. Leaf page UI is a separate root/media-agent task.

## Mutation and recovery contract

A null base hash is create-only. Delete, restore and confirmation require the displayed current hash. Every mutation requires a caller-owned request ID. The durable SQLite receipt binds the exact validated input and replays the saved response; reusing an ID for different input is a conflict. Failed transport/storage responses are marked `uncertain`; callers retain and retry the exact payload/ID instead of inventing a new mutation. Proposal pending decisions are persisted in the authenticated app database before dispatch and survive UI remount/restart, including a changed renderer port. The renderer waits for Brain UI state hydration before allowing a decision. No origin-bound browser storage holds the receipt identity.

Proposal views add `reviewedFingerprint` and `expectedPageHash` to the original shape. The fingerprint is case-sensitive and binds every reviewed field and originating coworker/session. Accept serializes fingerprint check, current-page hash check, page history/index update, proposal status and receipt. An outdated proposal must be rebased by its coworker before acceptance. `decidedBy` is the local user; page/revision author is derived from the stored proposing coworker, never caller-supplied.

Markdown publication is a committed SQLite journal, in the same transaction as history/status/receipt. Only after commit are private temporary files synced and renamed, then the directory synced and journal entries cleared. On a lost response or interrupted publication, startup or the next serialized operation finishes publication before serving state. SQLite errors before commit leave the original page and proposal unchanged. Markdown remains compatible with original Rerun; indexing is local FTS only, no embedding calls. Revision merging, original metadata and original page/hash shapes are preserved.

No tests, typecheck, lint, build, packaging, app interaction or model requests were run by this implementation agent. Root owns execution and native acceptance. Authored store, proxy, client and proposal-panel tests cover atomic acceptance, replacement/stale guards, receipt replay, publication recovery, no-network search, and pending-decision remount recovery.

Desktop system prompts require the explicit Brain grant and use a static review-only instruction. Company bytes are read only through the live permission checks on Brain tools; original hosted prompt readers and unavailable direct-write instructions are excluded on desktop.
