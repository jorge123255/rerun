## A/B — private local templates (W3 / B4)

Use `/api/desktop/templates` and `/api/desktop/templates/[templateId]` for the local library, read-only exact detail, capture planning, capture and installation. A defines strict request/response schemas in `desktop-templates.ts` and exports a server factory with injected existing workspace/store/engine authority. Every mutation has a stable `requestId`. Shared operations are `create-draft`, `sources`, `plan`, `capture`, `list`, `detail`, `install`, `receipt`; `create-draft {requestId,title}` returns `{templateId,revision}`, and subsequent plan/capture requests include that exact template identity/revision; capture/install must carry the server-issued exact plan or template revision. Server resolves local coworker IDs; no client engine IDs or filesystem paths.

A capture plan exposes safe metadata and explicit selectable files, original source revisions and required setup. Support one local workspace and selected existing coworkers, config/instructions, explicitly selected confined regular text files and user-owned skills. Exclude credentials/env files, chat/run/history databases, memories, provider account/model secrets, service/MCP rows, native grants and owned connector skills. Report exclusions. Preserve original template manifest semantics and labels where supported. No public publishing, hosted marketplace, paid catalog or remote URL import. Do not claim arbitrary private data is stripped from user-selected prose.

Import creates fresh immutable identities, separate folders and empty histories. No source overwrite, no inherited credentials/capabilities, no automatic execution or active routines. Persist receipt/progress before side effects; interruption must reconcile exact created identities instead of duplicating on retry. A's import boundary accepts C's injected `initializeImportedSetup({agentId, engineAgentId, importReceiptId, prompt, required, signal}): Promise<{revision:string}>`. It is idempotent for that exact trusted import identity and initializes only a fresh imported coworker; never accept those engine IDs from the browser. Before returning installed, an injected root server-side commit must persist the new local coworker rows, board placements and installation receipt together. Keep partial filesystem resources associated with the receipt for reconciliation. The UI callback only refreshes/navigates; closing the app before it runs cannot lose placement or cause another import. Any resource limits must be explicit and validated before expansion/write; reject traversal, links, duplicates and unexpected archive metadata.

B reuses original CaptureActions-shaped UI via a local adapter, original selection/review flow and library/detail layout. Read-only source selection/capture planning comes before confirmation. The adapter owns a canonical draft/plan ID server-side, not a local pathname. Install returns the ordered new coworker views plus durable receipt; B calls `onInstalled({ receiptId, coworkers })` once after acknowledgment. Root owns durable server-side placement and UI navigation; the callback never performs installation or placement. Retry the same request after uncertainty; "Use again" deliberately creates a new request. Do not load hosted library hooks/billing/actions. No template deletion in this slice.

No independent global singleton.

## E/F — suggested-app requests in chat (C6)

Preserve `suggest_service` as a delivered HITL request that ends its turn. Input is 1–20 unique exact catalog slugs with original bounded reason text; reject duplicates before delivering the ACK instead of silently deduplicating, using original `pendingServices` and result serialization. Do not add generic `request_secret` or `.env` storage. Apps credentials remain exclusively in the already integrated Apps lifecycle.

Route `/api/desktop/sessions/[sessionId]/service-requests`. E supplies strict contracts and exact source validation: local owner/session, delivered source message, tool call, fingerprint of the complete ordered request and decision revision. GET returns request identity/revision, ordered safe catalog details, current connection views, current index/choices and safe retry state. A failed catalog read is unavailable, never not-found. Unsupported auth is distinct from a missing/disabled catalog entry.

POST `progress` carries `requestId`, `serviceRequestId`, exact source guard, `expectedRevision`, currentIndex and ordered choices. Each entry is `{slug,choice:"pending"|"skip"}` or `{slug,choice:"use-connection",installation:{key,revision}}`; preserve that exact installation reference in the progress receipt. Persist no credentials or client health. POST `finish` carries the same authority fields; `expectedRevision` always means the current saved decision/card revision, while `installation.revision` is separate. Remaining pending choices block Finish; they are never implicitly skipped. Server derives connected/skipped/reset/not-found from current source and authoritative connection/grant state and seals exactly one secret-free `serializeServiceSetupResult` follow-up. Merely opening/closing/connecting Apps does not submit that message. Finish retries reconcile an existing receipt/run rather than send again. Refuse stale owner/source/installation revisions; no fabricated connected outcome. All use-connection rows require current healthy usable state and Apps grant, checked through existing authority. Do not give the request itself tool capability or enable Apps automatically.

F ports original ordered service cards, Connect/Cancel/Skip/Next/Finish, progress dots and receipt. Connect calls injected `onOpenApps({agentId,slug,serviceRequestId,sourceFingerprint,signal}): Promise<{status:"closed"}>`; root owns focused existing Apps navigation. The promise resolves only when that exact owned flow closes, never as a connected outcome. Abort/owner/request changes close or detach only the matching flow and reject the wait; they cannot close a newer dialog. Cancel closes configuration without changing choice, and after an ordinary close F refreshes only the still-current source request. No second credential form, hosted actions/OAuth, unsourced alternative suggestions or app install on mount. Cancel only closes setup; Skip records the explicit choice. Use async acknowledged callbacks, exact retry IDs and durable progress across tab/owner changes/restart. E derives the final names/outcomes/text; the browser cannot manufacture the result. Root owns request rendering, pending/queue/attention checks, grant/tool registration and run admission.
