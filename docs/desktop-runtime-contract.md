# Desktop preview runtime

The preview uses an Electron main process, a production Next child, and a separate engine child. It supports one local workspace and chat through API providers or a ChatGPT subscription. External MCP subprocesses, browser/computer tools, Claude subscription execution, schedules, workspace reset/deletion and public publishing are unavailable in this slice.

## Packaged resources

`runtime-manifest.json`, relative to the app Resources directory:

```json
{
  "protocolVersion": 1,
  "buildId": "source-commit-and-desktop-build-id",
  "nodePath": "runtime/node/bin/node",
  "uiRoot": "runtime/ui",
  "engineEntry": "runtime/engine/dist/cli/bin.js"
}
```

Paths are relative, confined to Resources, and checked after symlink resolution. `uiRoot/server.js` is the production standalone Next entry. Include its traced dependencies, public files and static chunks. Compile the engine with its compatible dependencies and assets. Compile/copy all files from `apps/desktop/src/main` to `apps/desktop/dist/main`; entry is `index.js` (which imports `index.mjs`). Keep `preload.cjs` and the startup HTML/CSS/JS alongside it.

The bundled Node runtime must match native libSQL/sharp modules. No runtime executable is resolved from the user's PATH.

## Persistent state

The app uses `~/Library/Application Support/Rerun Desktop Preview`. `identity.encrypted` holds the install ID, engine API key and credential-encryption key encrypted with Electron safeStorage; it fails closed if Mac secure storage is unavailable. Workspace 1 has a dedicated `workspaces/1/engine` directory and owner marker. Existing `~/.rerun` data is not adopted.

The **Memories** button in coworker chat lists that coworker’s saved Rerun notes. **Add memory** saves the content, kind and tags locally. Each note has its own delete confirmation. Listing, adding and deleting these notes works without a model call. The desktop routes resolve the local coworker before reading or changing its memory store.

**Clear all** uses Rerun’s confirmation dialog and clears all notes for that coworker, even when the current search has no matches. It also removes legacy Markdown notes and stale index entries. An accepted clear resumes after interruption. Other coworkers, non-memory files, recall and learning preferences remain unchanged.

**Recall memories** searches that coworker’s notes locally. Press Enter or choose **Search** to see up to five matches ranked by keyword relevance and memory strength. **Clear search** returns to the full list. Looking up a note in this panel does not increase its access count or strengthen it.

When a coworker has memory enabled, a chat message uses the same local keyword search. Up to five relevant, active memories can accompany the message to the selected chat provider, including notes saved only as Markdown. A note already present in the conversation context is skipped. Chat can refresh the last-use time of an indexed match without increasing its access count. Rerun’s separate automatic learning setting still controls whether the coworker reviews a completed exchange for facts to save or correct.

In **Edit coworker**, **Use saved memories in chat** controls whether a new turn retrieves notes. **Learn from replies** controls whether a completed exchange can add, correct or remove a learned fact. You can use saved notes with learning off. Switching recall off pauses learning and preserves the learning preference for when recall is enabled again. Rerun also pauses learning for coworkers whose existing self-improvement setting is off. The **Memories** panel still lets you manage saved notes manually.

**Attach from Files** in coworker chat selects one existing UTF-8 `.txt` or `.md` file of up to 32 KiB from that coworker’s workspace. The filename appears next to the draft, where you can remove it. When you send your question, the Mac app reads the file and sends that version to the selected provider as part of the message. The saved conversation shows the filename and uses the original text even if the workspace file later changes or is removed. A file that can no longer be read leaves the draft available to edit and retry.

On a coworker’s card, **Tools** separates Rerun actions from native Codex capabilities. Each switch belongs to the selected coworker and starts off. Existing file-read grants still apply. The engine can grant file reading, listing and searching individually, plus recall, writing and deletion of that coworker’s memories. File contents and tool results may reach the selected model. Files are limited to visible UTF-8 text in the coworker’s workspace. A read checks the grant again before returning up to 32 KiB. Memory changes require a current matching note. The expandable chat step and the run record preserve the actual tool outcome.

Codex receives the Rerun tools granted for that run through its authenticated loopback bridge. Native **Search the web** enables Codex’s web search. **Code mode** starts the bundled JavaScript helper for that coworker. Its isolated scripts can calculate and call granted tools. Changing the toolset starts a new Codex thread with the existing chat history. A native grant change during an active Codex reply requires stopping that reply first. Rows with missing runtime or external service prerequisites explain why they are unavailable.

**Run shell commands** and **Edit temporary files** are independent grants. Both use a separate native Codex worker with a temporary folder and no account credentials or network access. **Include workspace files** populates that folder with bounded copies of visible, singly linked text files owned by the coworker. Commands can change their temporary files. Quitting, cancelling, or finishing the turn discards those changes. Saving back to the original workspace needs its own approval and conflict-handling flow. The worker rejects unauthorized clients, unrelated paths, unauthorized file writes and unsupported commands.

In **Files**, **Import file** copies a single local `.txt` or `.md` document of up to 1 MiB into the selected coworker’s current folder. The final filename appears only once the full document is written. An existing name is preserved, including when two imports race. **Find chat** on the Team board searches local conversation titles across coworkers. Each result shows the coworker and opens that exact saved chat.

Selecting a tile or a Find chat result opens the coworker in Rerun’s shared side panel. At desktop widths it sits along the right edge of the isometric board. Narrow windows use the original bottom sheet. Closing the panel returns focus to the coworker’s tile and retains the board’s pan and zoom. The workspace menu provides access to Settings and coworkers.

Right-click a coworker’s tile, or focus the tile and press Shift+F10, then choose **Rename**. The Mac uses Rerun’s rename dialog and derives the @handle from the new display name. It keeps the same coworker and chat IDs. An open panel keeps its selected conversation and unsent text when the board label changes.

Choose **Duplicate** on a coworker’s tile, then click an empty spot or use **Place copy**. Escape or Cancel ends placement before a copy is made. A placed copy retains its board position and gets an independent coworker ID, workspace files, and conversation history. Its first chat starts empty. A retried placement returns the same coworker.

Choose **Disable** or **Enable** from the same tile menu. This Mac control uses the engine’s existing `enabled` setting and Rerun’s original grey, sleeping **Inactive** tile; the hosted board reserves deactivation for plan limits. The coworker stays in place and its chats, files, memories and settings remain intact. Disabled coworkers allow history reads but cannot start a new reply or regenerate one. An already-running reply can finish, and **Stop** remains available. Enabling restores sending to the same conversations. The engine configuration is authoritative; the local board projection is refreshed on startup and roster reads, including recovery after a lost save acknowledgement. A duplicate inherits its source’s enabled state.

Choose **Delete** to open Rerun’s confirmation dialog and type the selected coworker’s name. Cancel leaves it unchanged. A confirmed deletion removes only that coworker’s chats, files, memories and board tile; its original or other completed copies retain their own data. The dialog waits for confirmation from the engine and keeps failures visible for retry. Stop active replies or wait for work to finish before deleting. Local receipts and engine deletion markers allow interrupted cleanup to finish after restart and prevent an old duplicate request from restoring a deleted coworker. A different coworker’s open chat and draft stay open.

Open **Coworker card → Monitoring** to see that coworker’s run count, error rate, activity by status and runs by model. It opens on the last seven days and offers 24 hours, 30 days and 90 days. The view refreshes while visible. Cost and token totals appear only when all runs in that period have complete supporting measurements.

The board projects pending question and approval cards from the same receipt-aware readers used in chat. A waiting coworker uses Rerun’s original cyan hand indicator and **Waiting for you** label; accessibility navigation also announces **Needs you**. A running reply retains the original Working precedence and carries its pending-request count. Selecting a coworker with a confirmed request, including through its Open chat menu action, opens its newest pending local conversation. The existing chat card revalidates the request before accepting any response. The board does not answer, dismiss or execute it.

`GET /api/desktop/attention` exposes only local coworker/chat identifiers, kind, bounded summary, names, enabled state and updated time. It returns known items and unavailable coworker IDs separately; incomplete history never means zero pending. The board activity route shares the same read-only scan with the Actions inbox. Reads are bounded to four history requests at a time, share an overall deadline, and coalesce only while in flight. Late roster changes, deletion, failed reads and foreign history cannot restore a stale navigation target. Disabled coworkers keep their Inactive tile and can open pending history without becoming enabled.

The board’s **Actions** pill opens Rerun’s inbox presentation for pending questions and approvals across local coworkers. Opening a row closes the inbox and opens that exact saved chat without submitting a decision. The inbox polls while open and visible, preserves its last known count while closed, and distinguishes loading, partial/unavailable reads and confirmed zero pending. Current roster membership and exact item identity are checked again before navigation. Explicit Close or Escape returns focus to the pill; outside clicks leave focus with the clicked control.

The coworker panel uses Rerun’s **open chat tabs**. Select **+** to start a chat, or choose a saved conversation from Chats or Find chat to open it in the strip. Each conversation has its own messages, model choice and running reply. The Mac database remembers up to eight open tabs and the active tab per coworker across launches. Closing a tab keeps its conversation in Chats.

Ordinary **unsent drafts** are stored in the Mac database by coworker ID and stable tab UID. Each stores up to 20,000 characters of exact text and an optional relative path to a selected file owned by that coworker. File bytes are read when sending, as described under **Attach from Files**. Drafts survive panel changes, disabling a coworker, app restart and changed loopback ports. Closing a tab discards that tab’s ordinary draft and retry receipts while keeping its saved conversation; deleting a coworker removes only its drafts. Queued follow-ups have their own separate persistence.

The authenticated `/api/desktop/agents/:agentId/draft` route requires a currently open, owned tab. GET is read-only. PUT uses a comparison revision and immutable request UUID; stale writes return the current saved draft with a conflict. The UI offers **Keep this draft** or **Use saved draft**. State and receipts commit together, with the latest 64 request receipts retained per tab. An exact retry returns the current state without reapplying old text; an evicted old save remains blocked by its stale revision. Empty drafts retain their revision so a delayed write cannot restore cleared text. DELETE compares the supplied revision, text and attachment path before clearing, and leaves a newer draft untouched. Tab layout changes and draft mutations share the same serialization and transaction boundary for transfers and cleanup.

Draft restoration and saving wait for preceding tab writes. A first send keeps its tab UID when the engine returns the new conversation ID, so text typed while that send starts remains attached to the same composer. Sending first flushes the draft; a confirmed message or queued-message acceptance clears it only if its local edit version is unchanged. Newer text or attachment choices remain. Writes coalesce behind an in-flight save, and a failed acknowledgement retries the same UUID before saving a newer edit. Failed saves remain visible with **Retry saving draft**.

While a reply is running, **Send** saves one follow-up for that conversation using Rerun’s queued-message pill. **Send now** stops the preceding reply and waits for its transcript to settle before sending; **Remove** discards only that queued item. A queued attachment is read from the same coworker when the message is accepted. The saved message, attachment snapshot and run receipt are committed together, so retries with the same ID do not create another turn. Queues live in the Mac database and survive changed loopback ports. Reopening a queue behind its exact still-running reply retains it; after an interrupted or finished reply it returns for review. An uncertain send is reconciled against its saved receipt before another attempt. Queued Codex turns use saved history in a fresh native thread while retaining their conversation’s model, reasoning and tool grants.

The composer’s model picker can follow the workspace model, star a coworker default, or choose a model for just one conversation. A new chat’s choice is saved on its first send. An alternate created with **Regenerate reply** inherits an explicit chat choice, while an alternate of a chat following defaults continues to follow them.
**Edit** in Files saves an existing `.txt` or `.md` file only when its text still matches the hash from when it was opened. The draft is a hidden file in that same folder, not a second copy to edit. macOS can replace a name atomically with `rename`, and `renamex_np` with `RENAME_SWAP` can exchange the draft with the current file without a gap. Neither call can see a writer that already holds the file open, or a parent folder that moves during the call, and a path check before the call is too early to see it. The save keeps the previous bytes under a hidden backup, then links the draft into the name. If that open folder now belongs to another coworker, the draft is removed and the response includes no file text. If another writer’s bytes are newer, those bytes stay under the normal name or are put back there, and the editor shows a conflict. Before the displaced inode is retired, the Mac checks whether any process still holds it. If it is held or that cannot be established, the external version is restored to the original path and visible `<name>.draft-<id>` and `<name>.external-<id>` recovery copies preserve both versions; the conflict dialog names both files. Retirement moves the hidden name aside and verifies its inode before deletion, so a different file arriving at that path is not deleted. There is a short gap after the name is set aside and before the draft is linked. If the app stops in that gap, the next time this Mac lists the folder or opens the file it restores the backup, or it keeps the name when the draft was already published.

**Rename** in Files changes one file or folder within its current folder. It reuses Rerun’s Rename menu and inline name field: the name before the last dot is selected, Enter submits once, Escape cancels without closing Files, and an empty or unchanged name cancels. Navigation and dismissal wait for a submitted rename. The Mac list does not add Download, Move or New folder. Path separators, symlinks and occupied destinations are refused. A bundled native helper uses exclusive rename with parent/source inode checks; it needs no Python, compiler or shell on the installed Mac. Every rename, including case-only changes, stages through a private name with a versioned journal. Recovery rechecks the parent before each mutation and never replaces an arriving source or destination. If both normal names have become occupied, a visible rename-recovery copy preserves the staged entry and the UI reports the conflict. A file moved or replaced after opening cannot be saved through the old editor identity, even when its bytes match. Successful saves refresh that identity for the next edit. Saved chat attachment snapshots are not rewritten.

**Delete** in Files removes one selected file or folder after a confirmation that names it. The wording matches Rerun’s file list: `Delete <name>?`, “The file is deleted from the box. This cannot be undone.”, or for a folder “The folder and everything inside it are deleted from the box. This cannot be undone.” Cancel sends nothing. The Mac does not use the cloud recursive remove. It pins the parent directory, refuses the workspace root, symlinks, reserved recovery names and a path whose inode is no longer the one the list showed, and moves a file aside with the same exclusive rename helper before unlinking that private name. Each file or empty directory gets an immutable v2 move receipt before exclusive staging, with source, parent and workspace identities. A folder is walked through directory descriptors; every opened directory revalidates its own canonical path and inode together with its ancestors before recovery or mutation. Even an empty folder is staged exclusively and rechecked before private-name removal. A failed move restores the exact staged inode to its free original name, or preserves it as a visible delete-recovery copy without replacing an arriving file. An interrupted delete resumes only journaled inodes the next time that folder is listed, and does not resume inside another coworker’s workspace. Journals remain while private stages or sidecars need recovery. The final private-name removal is checked immediately before the syscall; it is not an atomic inode-conditional unlink. Deleting a file does not select a sibling and does not rewrite a saved chat attachment or composer path.

**Context compaction** uses the original CompactionStep during a live turn. Running, completed and explicit error events come from the engine, with validated nonnegative counts. Updates for one checkpoint keep its position and replace its prior state; an unfinished running row disappears when streaming ends rather than becoming a fabricated failure. Desktop streams emit their stable run message ID before history preparation and suppress the later provider start, so pre-reply compaction and the reply stay in one assistant message. Hosted stream behavior is unchanged. Saved checkpoints contain the context summary and cursor, not emitted display counts/status; reopening saved history therefore does not invent a compaction row.

Assistant replies render Markdown in live and reopened chats, including headings, lists, tables and fenced code blocks. **Copy reply** copies the answer’s original Markdown. The user’s message stays literal text, including its attachment label. Markdown images display their alt text, and eligible HTTPS links open in the system browser when clicked.

When an assistant reply includes structured citations from its provider, **Used 1 source** or **Used N sources** expands beneath that reply. A cited HTTPS address opens in the system browser. A cited document without a public address appears by title or filename. Citations stay with their assistant message through tab changes and restart. A Markdown link by itself does not create a citation. The packaged Codex login provider currently sends no source events.

When a coworker puts an email, post or message in a `draft` fence, the answer shows a separate card. The fence title labels the card, or it reads **Draft** when the title is empty. **Copy draft** copies just the card’s plain text, preserving its spacing and literal Markdown. While the answer is streaming, the card can be copied as soon as its fence closes. Reopening the conversation renders the cards from the saved reply.

**Regenerate reply** opens an alternate chat for the same coworker. Choose a completed answer and the model receives the conversation through the question that prompted it, including the saved attachment text and recalled notes from that turn. The original chat keeps all its answers and run history. The alternate has a separate run, can be stopped independently, and appears in Chats and Find chat with an **Alternate ·** title.

Regeneration flushes the source draft and temporarily freezes its composer and file selection. When the alternate is accepted, one database transaction saves the new tab layout, transfers the original chat’s text and selected file path to its new tab UID, and advances the reused live UID to an empty draft for the alternate. The composer reloads only after that layout write succeeds. A stale autosave cannot restore the source text into the alternate, and a repeated layout acknowledgement does not repeat the transfer or erase a newer alternate draft. A failed layout commit rolls back the transfer.

A completed, saved assistant reply can be rated with **Good response** or **Bad response**. The vote is saved on the click. Optional details use Rerun’s issue categories and a 5,000-character note. Closing the details dialog keeps the vote. Choosing the same thumb again removes it, and choosing the other thumb clears the previous note. The dialog says the feedback is stored on this Mac. The Mac checks that the reply’s stable id is an assistant message in the selected coworker’s selected conversation before it writes. The same answer text in another chat, or the same chat opened for another coworker, keeps its own vote. A vote stays out of the model request and is not uploaded. The source list and **Copy reply** stay separate actions.

At each launch, main atomically writes mode-0600 `runtime.json`:

```json
{
  "protocolVersion": 1,
  "launchNonce": "random-uuid",
  "buildId": "same-as-resource-manifest",
  "workspaceId": 1,
  "dataRoot": "absolute-profile-root",
  "app": { "origin": "http://127.0.0.1:actual-ui-port", "sessionToken": "64-hex-random" },
  "engine": { "origin": "http://127.0.0.1:actual-engine-port", "apiKey": "64-hex-random" }
}
```

This file is server-only. The renderer must never receive it or the engine credential. Main sets an HttpOnly, SameSite=Strict `rerun-desktop-session` cookie before navigating to `/desktop`. Local UI routes authenticate this cookie and check Host/Origin; callbacks authenticate the engine separately. Loopback binding does not replace authentication.

## Startup

Main passes `RERUN_DESKTOP_APP=1`, `RERUN_DESKTOP_DATA_DIR`, and `RERUN_DESKTOP_RUNTIME_FILE` to both children. The UI also gets `RERUN_DESKTOP_UI_ROOT`, `HOSTNAME=127.0.0.1` and `PORT`. UI wrapper imports `uiRoot/server.js` and terminates on parent IPC disconnect.

Main waits for authenticated `GET /api/desktop/health` returning `{status:"ready",protocolVersion:1,launchNonce,buildId,workspaceId:1}` after local DB initialization. This route must not require an already-running engine. Main then starts `node engineEntry desktop-run` with loopback host/port, engine root/key, actual local hub origin, `RERUN_DESKTOP=off`, and the install encryption key in `RERUN_DESKTOP_SECRET_KEY`.

The engine validates the manifest, prepares its data directory, reconciles interrupted state, and listens. It sends IPC `{type:"ready",status:"ready",protocolVersion:1,launchNonce,buildId,workspaceId:1}`. Main also verifies bearer-authenticated engine `/health` before loading the UI. Both nonce and build ID must match. Failed starts use bounded retry and never adopt a pre-existing listener.

## Stop and limits

Before explicit Quit stops services, the trusted desktop renderer flushes drafts through the preload’s `onBeforeQuit` bridge. Main validates the current window, main frame and `/desktop` origin, and accepts only the matching registration and quit-request acknowledgement. Navigation or renderer loss invalidates that registration. The renderer freezes new edits and sends while it waits for accepted-send bookkeeping, pending tab writes and all draft writes, including composers that are no longer visible. It stays frozen after a successful acknowledgement until shutdown or an explicit quit cancellation.

If saving fails, a conflict remains, or the flush acknowledgement times out after ten seconds, the Mac dialog offers **Stay** by default or **Quit without saving**. Stay keeps the services running and resumes the composer so the user can retry or resolve the draft conflict. Quit without saving explicitly permits losing the latest unsaved changes. A successful flush proceeds to the normal service shutdown below; it does not wait for an already accepted assistant reply to finish generating.

Main sends `{type:"stop"}` to the engine before stopping the UI, keeping callbacks alive while runs settle. Engine rejects new work, cancels and awaits active run cancellation, closes MCP and HTTP, acknowledges stop, then exits. Main has a bounded grace followed by forced termination of the owned PID. No arbitrary subprocess tools are enabled, and children react to parent IPC loss. Window close hides the app on macOS; explicit Quit stops services. No login item or hidden daemon is installed.

The preview is not a general-distribution release. Native computer control, Claude subscription execution, general connectors, workspace reset/deletion, migration from an existing install, telemetry consent, public publishing, signing/notarization and update hosting require their own validated integrations.


## ChatGPT device-code sign-in

Settings → AI providers → Connect ChatGPT (Codex) starts device authorization on the bundled Codex app-server. It returns a verification link and short code. Once OpenAI approves, the engine reads the ChatGPT account and runner model catalog, registers the connection, and selects its default model. The CLI owns refresh and stores credentials in the macOS Keychain scoped to a separate Rerun Codex home. Rerun stores connection metadata and a sign-in flag, not the OAuth tokens. Cancel or sign out in the same panel.

Opening the connected Codex panel or choosing **Refresh models** reloads every page of models the runner offers for chat. Rerun keeps the selected model while it is available and retains the saved catalog if a refresh fails. The reasoning-effort picker uses the levels reported for that model. Its selection is stored with the workspace default and applied to the next coworker turn, including in an existing conversation. **Model default** uses the effort recommended by Codex.

Both streaming chats and one-shot model calls use the pinned arm64 runner via the verified resource manifest. Its launcher clears the environment, applies a macOS sandbox, and uses a private working directory. Rerun does not borrow a personal Codex login or launch the user's installed CLI.
